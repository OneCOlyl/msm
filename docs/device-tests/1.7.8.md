Found while testing: the game build can't read `Collider.enabled` (`ICall … get_enabled was not resolved`), so a chest
counts as lying while its `Obj_ItemPos` marker is active. A chest's `localPosition` equals its world position.

## 1.7.8

The host log shows `кооператив 1.7.8 включён`. A chest goes to one player: the guest's copy is locked by moving its
collider centre, a guest at the chest sends a request, and the host gives the chest to the first request.

| What | Result | Notes |
|---|---|---|
| Distance at which the game picks up a chest | ✅ | Host chest at (3; 2), hero moved in horizontally: not picked at 0.5, picked at 0.4. Guest request radius 0.5 |
| Locked copy isn't picked up, unlocked copy is | ✅ | 2026-11-04. The guest's request was muted (`ClaimAt` far in the future), the guest hero stood on the copy for 4 s: no window, the chest stayed. After unmuting: `хост отдал его мне`, the «Treasure Chest» window, the host logged `отдан «Игрок 84»` |
| Choosing an artifact from a chest | ✅ | 2026-11-04, after the fix below. The guest took the host's chest and chose an artifact; the game kept running |
| Chests from artifact 75 | ✅ | 2026-11-04. 75 written into `V_Artifact_Manager.List_ArtifactSelectID`. Host: `окно выбора положило мне 3 — они только мои`, the guest got no copies. Guest: the same line, all 3 chests still lying 5 s later |

Found and fixed: the game crashed when an artifact was chosen from a chest (guest SIGSEGV, host abort
`pthread_mutex_lock called on a destroyed mutex`). The cause is any Harmony hook on
`V_Artifact_Manager.Button_Artifact_Select`: an empty `coop_debug hookm` hook crashes the game with `coop` disabled too,
and without hooks the choice works. 1.7.8 no longer hooks the choice buttons. Chests that appear during the player's own
pause (the choice window) are personal.
