# Testing 1.7.8 on phones

Date: 2026-11-03. Claude Code installed the builds, tapped buttons through adb, called the `coop_lab` test ground and
game methods through the `coop_debug` console, and read `modkit.log` on both phones.

| Phone | Android | Resolution | Role |
|---|---|---|---|
| Xiaomi 25042PN24C | 16 | 1440×3200 | host |
| Google Pixel 3a | 12 | 1080×2220 | guest |

The table below was taken on 1.7.7 (both logs show `кооператив 1.7.7 включён`). In 1.7.8 a guest's pickup goes
through a request to the host, see the «1.7.8» section. The room was created and joined through the console, without a VPN.
Shared enemies and shared pause on, heroes immortal, experience off. Area: Arrays.

New: shared chests. Only this was tested; the rest of the checklist was not run.

| What | Result | Notes |
|---|---|---|
| Lobby button | ✅ | Host and guest both show «Сундуки: общие, берёт кто первый» below the lobby label. Tapping it at the host switches to «у каждого свои» and back (`лобби: сундуки …` in the log) |
| Host's chest at the guest | ✅ | `CreateItem_Position 5 1 3 2` at the host: the guest logs `сундук #1 хоста (вид 5): копия у меня в (3.0; 2.0) от старта`, the chest and its arrow are visible |
| Guest picks up | ✅ | The guest got the «Treasure Chest» window. The host removed its chest in the same second, while the guest's window was still open (timeScale 0), and showed «Игрок 84 забрал сундук». On 1.7.6 the host waited until the guest closed the window: the chest step was paused |
| Host picks up | ✅ | Kind 6 chest at (−4; −3): the host picked it up, the guest's copy and arrow disappeared within half a second |
| Guest's own chest | ✅ | `CreateItem_Position 5 1 2 3` at the guest: `сундук: свой у гостя убран — сундуки кладёт хост` |
| Chests the game places itself | — | The host's game placed a kind 5 chest at 0:30 by itself. Its copy at the guest wasn't checked in that battle |

Found while testing: the game build can't read `Collider.enabled` (`ICall … get_enabled was not resolved`), so a chest
counts as lying while its `Obj_ItemPos` marker is active. A chest's `localPosition` equals its world position.

collider centre, a guest at the chest sends a request, and the host gives the chest to the first request.

## Known limitations

- The main 1.7.8 change is not tested on phones: that the guest's game doesn't pick up a locked copy and picks it up
  once the host gives the chest away. The scenario passes only in ModSim.
- Chests from artifacts 75 and 104 and ability 112 were found in the game code (`Button_Artifact_Select`,
  `Button_SelectAbility`) and were not triggered on a phone.
- The rest of the required checklist was not run: 1.7.8 changes only chests and the lobby.
