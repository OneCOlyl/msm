## Структура репозитория

| Путь | Что там |
|---|---|
| `mod/coop/` | Исходники мода. `Net/` — сетевой код без зависимостей от Unity (клиент, встроенный сервер, протокол). |
| `mod/coop_lab/`, `tools/lab.py` | Полигон: в бою кнопка «ПОЛИГОН» (спокойная арена, любые мобы, механики боя) и сценарии проверок кооператива на двух телефонах. Игрокам не нужен. |
| `tools/terra.py` | Автобой на Terra вдвоём: окна выбора, сундуки, торговец, обелиски. |
| `tools/phones.py` | Прогон на двух телефонах по USB без рук: установка сборки из `dist/`, перезапуск игры, подключение, вход в бой, сценарии `lab.py`, журналы. |
| `mod/coop_debug/`, `tools/coop_dbg.py` | Отладочная консоль: порт 8770 на телефоне, читать и менять поля игры во время боя. Игрокам не нужна. |
| `mod/coop_cheat/` | Чит: в бою кнопка «ЧИТ» выдаёт уровни заклинаний, особенностей, комбинаций, синергий и героя. Игрокам не нужен. Три мода разработчика описаны в [TOOLS.ru.md](TOOLS.ru.md). |
| `tools/release_notes.py` | Описание релиза: изменения из `.github/release_notes.md` с прошлого опубликованного релиза (его вызывает workflow `release`). |
| `server/coop_server.py` | Отдельный сервер комнат (Python 3.8+) — если сервер нужен не внутри игры, а, например, в Termux или на ПК. |
| `server/coop_client.py` | Проверка связи без игры. |
| `tests/NetTest` | Тесты сети. Одни и те же проверки идут против встроенного сервера и `coop_server.py`: ответы, коды ошибок, слоты, переподключение и ограничения у обоих должны совпадать. |
| `tests/server_test.py` | Проверки `coop_server.py` изнутри: счётчик входов с адреса (окно, забывание, предел адресов) и обратное давление по каждому получателю. |
| `tests/ModSim` | Имитация игры: два экземпляра мода (хост и гость) в одном процессе. |
| `tests/DebugSim` | Проверка отладочной консоли: разбор команд, закрытие порта при выключении. |
| `tests/CheatSim` | Проверка чита на фальшивой игре: выдача и снятие уровней, уровень героя, все магии на максимум. |
| `stubs/` | Заглушки Unity для сборки без телефона. |
| `libs/` | `ModKit.dll` и `modkit_*.dll` (в том числе `modkit_spells_data.dll` для чита) из релиза MS_KIT 2.0 (MIT) — только для сборки. Хэши — в `libs/SHA256SUMS`, их проверяет CI. |
| `docs/` | Документация, исследования игры, чек-лист и результаты проверок на телефонах. Каждый документ есть на английском (`*.md`) и русском (`*.ru.md`); правьте оба. |
| `.github/workflows/` | `ci.yml` — сборка и тесты на каждый push; `release.yml` — публикация релиза «Кооператива»; `tools-release.yml` — релиз инструментов разработчика по метке `tools-*`. |
| `.github/release_notes.md` | Список изменений по версиям; в описание релиза попадают изменения с прошлого релиза. |

## Сборка и тесты

Нужны .NET SDK 8, Python 3 и bash (на Windows — Git Bash).

```bash
bash build.sh
```

Скрипт собирает заглушки Unity, проверяет совпадение версий, собирает `coop`, `coop_debug`, `coop_cheat` и
`coop_lab`, упаковывает их в `dist/<мод>.zip` и прогоняет все тесты. Если тесты не прошли или
версии не совпадают, скрипт завершается с ошибкой. `SKIP_TESTS=1 bash build.sh` — только сборка и упаковка.
Тесты идут параллельно, около 80 с: дольше всех ModSim (раздел 7 — отдельным процессом, `ModSim.dll 7`, остальное —
`ModSim.dll main`). Новому тесту с сетью нужен свой порт.

Сборка против настоящих сборок игры (папки `net8/` и `il2cpp/`, скопированные с телефона после первого запуска
Zombix):

```bash
REF=/путь/к/ref bash build.sh
```

## Статический анализ

- C#: анализаторы .NET (`Directory.Build.props`, уровень `latest-recommended`), их предупреждения видны при сборке.
  Отключённые правила — в `.editorconfig`.
- Python: `ruff check .` (правила — в `ruff.toml`).
- `build.sh`: `shellcheck build.sh`.

CI не пропускает замечания ruff и shellcheck.

## Проверка на телефоне

Два телефона на USB, на обоих ModKit и библиотеки MS_KIT, у гостя в настройках coop указан IP хоста. Тогда всё делает
один скрипт:

```bash
python tools/phones.py run --build                  # сборка, установка, перезапуск, связь, бой, lab.py mobs drop, журналы
python tools/phones.py run --no-deploy --lab "spells --spells 13,17"
python tools/phones.py status                       # версии модов на телефонах и состояние coop
```

Шаги по отдельности: `deploy`, `restart`, `connect`, `battle [--area N] [--loop]`, `logs`. Итог — PASS/FAIL и код
выхода, журналы обоих телефонов — в `dist/phones/<время>/`. Скрипт:

- ставит архив, только если на телефоне другая версия: архив той же версии ModKit не перечитывает (для `coop` это FAIL);
- после `am force-stop` удаляет `running.lock`, иначе ModKit сочтёт перезапуск падением и выключит моды;
- включает `coop`, `coop_debug`, `coop_cheat`, `coop_lab` в `config.json`, если они выключены;
- подключает и входит в бой через консоль `coop_debug` (`Host`, `Join`, `Button_AreaStart`), без нажатий по экрану;
- после проверок ищет исключения Unity в logcat и ошибки в `modkit.log` с последнего запуска coop.

На Terra (`--area 14`) до подбора особого обелиска бой стоит и враги пропадают, поэтому сценарии `lab.py` там не идут.
Для Terra есть автобой:

```bash
python tools/terra.py --minutes 6        # перезапуск, бой на Terra вдвоём, всё до 6:00, журналы в dist/terra/<время>/
```

Скрипт нажимает кнопки окон через `coop_lab` (`Buttons`, `Click`), касаний нет. Умение и атрибут — верхняя карта.
Усиление магии — первая магия сверху слева, в каждом следующем окне следующая вправо по рядам. Сундук — первый
артефакт. Торговец — первый товар, если хватает маны (игра тогда включает Buy), затем выход. Хост встаёт на обелиски
(`Pickups`, `GoTo`), оба — на сундуки и торговца. Героев никто не водит, поэтому у обоих бессмертие полигона. Окно, которого
скрипт не знает, он пишет в вывод со списком кнопок и скриншотом.

Вручную:

Установить свежую сборку по USB:

```bash
adb push dist/coop.zip /sdcard/Download/
```

Затем в Zombix: «Моды» → «+» → `coop`. Журнал мода:

```bash
adb shell cat /sdcard/MelonLoader/com.vkslrzm.Zombix/UserData/ModKit/modkit.log | grep "\[coop\]"
```

Перед проверкой убедитесь, что в журнале есть строка `кооператив <версия> включён`.

Отладочная консоль (`coop_debug` включён на телефоне) доступна только через USB:

```bash
adb forward tcp:8771 tcp:8770
python tools/coop_dbg.py 8771 "get mgr.Time_Sec"
```

### Полигон

`coop_lab` включается в окне «Моды» (новый мод ModKit по умолчанию выключен). В бою кнопка «ПОЛИГОН» открывает
три вкладки:

- «Арена»: спавн игры, бессмертие, опыт (без опыта нет окон выбора магии, кнопка уровня героя в чите работает), стоп и
  перемотка часов, убрать или убить врагов;
- «Мобы»: любой тип врага (0–50), эпические, особые, переход;
- «Механики»: часы к боссу, босс-волна, обелиск, смена области, притягивание маны, предмет по номеру.

Те же действия с ПК через консоль: `call T:coop_lab:MagicSurvivalLab.Lab/Current.Spawn 6 10`, `.Status`, `.CoopStatus`.
Магии выдаёт `coop_cheat`, полигон зовёт его в `Spell <id> <уровень>`.

Сценарии на двух телефонах (оба в бою, на связи, с `coop`, `coop_debug`, `coop_lab` и `coop_cheat`):

```bash
python tools/lab.py mobs drop spells                 # всё; --spells 13,17 --wait 20 — выбранные магии
python tools/lab.py --shots shots magic              # все магии, особенности и комбинации (~35 мин)
```

`mobs` проверяет, что мобы хоста всех видов появляются у друга, `spells` — что магии хоста видны у друга, `drop` —
переподключение после обрыва и сошедшиеся часы, `magic` — что каждый снаряд каждой магии, особенности (특성) и
комбинации (MagicCom) хоста повторяется у друга и что в журнале игры нет исключений. Перед проверками сценарий включает обоим бессмертие, выключает опыт и
снимает магии.

Отдельный сервер и проверка связи без игры:

```bash
python server/coop_server.py --port 8766
python server/coop_client.py <IP> 8766    # затем команда join
```

## Протокол v2

JSON-строки (UTF-8, одна строка — одно сообщение, не длиннее 16 КБ) поверх TCP, порт по умолчанию 8766.

- **Клиент → сервер:** `CREATE_ROOM`, `JOIN_ROOM`, `PLAYER_STATE`, `EVENT`, `PING`, `LEAVE_ROOM`.
- **Сервер → клиент:** `WELCOME`, `ROOM_CREATED`, `ROOM_JOINED`, `PLAYER_JOINED`, `PLAYER_LEFT`, `REMOTE_PLAYER_STATE`,
  `REMOTE_EVENT`, `PONG`, `ERROR`.

Хост отправляет `CREATE_ROOM` и после обрыва возвращается в свою комнату `JOIN_ROOM` с её кодом. `JOIN_ROOM` с пустым
кодом заходит в комнату на сервере; если комнат нет, отдельный сервер создаёт её, а сервер в игре хоста отвечает
`room_not_found` («Хост ещё не создал игру»), и клиент повторяет попытку. Если порт закрыт, клиент перебирает порты
от заданного до +4.

Поле `protocol` в `CREATE_ROOM`/`JOIN_ROOM`: нет поля — старый клиент, пускаем; иначе только целое `2`, всё остальное —
`protocol_mismatch`. Версию самого мода сервер не сверяет.

Коды ошибок: `room_full`, `room_not_found`, `protocol_mismatch`, `server_busy` (подключений или комнат слишком много),
`rate_limited` (слишком частые входы), `not_in_room`, `invalid_json`, `invalid_message`, `message_too_large`,
`unknown_type`.

Ограничения встроенного сервера: 32 подключения, 8 с одного адреса, 16 комнат, 60 входов в комнату в минуту с адреса,
30 с на вход в комнату после подключения, 40 с без данных — отключение.

## Выпуск новой версии

1. Поднимите версию в трёх местах: `version` в `mod/coop/mod.json`, `ModVersion` в `mod/coop/CoopMod.cs` и `<Version>` в
   `mod/coop/coop.csproj` (`build.sh` проверяет, что они совпадают).
2. Допишите изменения в начало `.github/release_notes.md` разделом `## Co-op <версия>`: сначала по-английски, затем то же по-русски после строки `**По-русски:**`. В описание релиза попадают
   только разделы, которых не было в прошлом опубликованном релизе (`tools/release_notes.py`). Остальная история
   остаётся в файле.
3. Проверьте сборку на двух или более телефонах по [чек-листу](RELEASE_CHECKLIST.ru.md) и запишите результаты в
   `docs/device-tests/<версия>.md` (английский) и `docs/device-tests/<версия>.ru.md` (русский).
4. На GitHub откройте Actions → release → Run workflow. GitHub соберёт мод, прогонит тесты и опубликует релиз
   `v<версия>` с `coop.zip`; результаты проверки попадут в описание релиза. Без файла результатов релиз не
   публикуется; русский файл добавляется, если он есть.

Инструменты разработчика (`coop_debug`, `coop_cheat`, `coop_lab`) выходят отдельно по метке `tools-<номер>`: см.
[TOOLS.ru.md](TOOLS.ru.md#выпуск).
