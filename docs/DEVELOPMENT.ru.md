## Структура репозитория

| Путь | Что там |
|---|---|
| `mod/coop/` | Исходники мода. `Net/` — сетевой код без зависимостей от Unity (клиент, встроенный сервер, протокол). |
| `mod/coop_lab/`, `tools/lab.py` | Полигон: в бою кнопка «ПОЛИГОН» (спокойная арена, любые мобы, механики боя) и сценарии проверок кооператива на двух телефонах. Игрокам не нужен. |
| `tools/terra.py` | Автобой на Terra вдвоём: окна выбора, сундуки, торговец, обелиски. |
| `tools/phones.py` | Прогон на двух телефонах по USB без рук: установка сборки из `dist/`, перезапуск игры, подключение, вход в бой, сценарии `lab.py`, журналы. |
| `mod/coop_debug/`, `tools/coop_dbg.py` | Отладочная консоль: порт 8770 на телефоне, читать и менять поля игры во время боя. Игрокам не нужна. |
| `mod/coop_cheat/` | Чит: в бою кнопка «ЧИТ» выдаёт уровни заклинаний, особенностей, комбинаций, синергий и героя. Игрокам не нужен. Три мода разработчика описаны в [TOOLS.ru.md](TOOLS.ru.md). |
| `tools/release_notes.py` | Описание релиза: изменения из `.github/release_notes.md` с прошлого опубликованного релиза (его вызывает workflow `release`). |
| `tools/check_comments.py` | Падает, если в `mod/` есть XML-документация `///`: комментарии только «почему», обычным `//` (запускает CI). |
| `server/coop_server.py` | Отдельный сервер комнат (Python 3.8+) — если сервер нужен не внутри игры, а, например, в Termux или на ПК. |
| `server/coop_client.py` | Проверка связи без игры. |
| `tests/NetTest` | Тесты сети. Одни и те же проверки идут против встроенного сервера и `coop_server.py`: ответы, коды ошибок, слоты, переподключение и ограничения у обоих должны совпадать. |
| `tests/server_test.py` | Проверки `coop_server.py` изнутри: счётчик входов с адреса (окно, забывание, предел адресов) и обратное давление по каждому получателю. |
| `tests/ModSim` | Имитация игры: два экземпляра мода (хост и гость) в одном процессе. |
| `tests/DebugSim` | Проверка отладочной консоли: разбор команд, закрытие порта при выключении. |
| `tests/CheatSim` | Проверка чита на фальшивой игре: выдача и снятие уровней, уровень героя, все магии на максимум. |
| `stubs/` | Заглушки Unity для сборки без телефона. |
| `libs/` | `ModKit.dll` и `modkit_*.dll` (в том числе `modkit_spells_data.dll` для чита) из релиза MS_KIT 2.0 (MIT) — только для сборки. Хэши — в `libs/SHA256SUMS`, их проверяет CI. |
| `docs/` | Документация, исследования игры, чек-лист и результаты проверок на телефонах. Каждый документ есть на английском (`*.md`) и русском (`*.ru.md`); правьте оба. |
| `.github/workflows/` | `ci.yml` — сборка и тесты на каждый push; `release.yml` — публикация релиза «Кооператива»; `tools-release.yml` — релиз инструментов разработчика по метке `tools-*`. |
| `.github/release_notes.md` | Список изменений по версиям; в описание релиза попадают изменения с прошлого релиза. |

## Сборка и тесты

Нужны .NET SDK 8, Python 3 и bash (на Windows — Git Bash).

```bash
bash build.sh
```

Скрипт собирает заглушки Unity, собирает `coop`, `coop_debug`, `coop_cheat` и `coop_lab`, упаковывает их в
`dist/<мод>.zip` и прогоняет все тесты. Если тесты не прошли, скрипт завершается с ошибкой. `SKIP_TESTS=1 bash build.sh`
— только сборка и упаковка.

Версия в репозитории не хранится: в `mod.json` и `.csproj` стоит `0.0.0-dev`. `build.sh` берёт её из `VERSION` (для
всех четырёх модов), иначе от ближайшей метки git (`git describe`: `vX.Y.Z` у `coop`, `tools-X.Y.Z` у модов
разработчика), иначе `0.0.0-dev.<число коммитов>`. Сборка с незакоммиченными правками получает `-dirty.<время>`: архив
той же версии ModKit не перечитывает. Версия попадает в dll и в `mod.json` внутри архива; файл в репозитории не
меняется.
Тесты идут параллельно, около 80 с: дольше всех ModSim (раздел 7 — отдельным процессом, `ModSim.dll 7`, остальное —
`ModSim.dll main`). Новому тесту с сетью нужен свой порт.

Сборка против настоящих сборок игры (папки `net8/` и `il2cpp/`, скопированные с телефона после первого запуска
Zombix):

```bash
REF=/путь/к/ref bash build.sh
```

## Статический анализ

- C#: анализаторы .NET (`Directory.Build.props`, уровень `latest-recommended`), их предупреждения видны при сборке.
  Отключённые правила — в `.editorconfig`.
- Python: `ruff check .` (правила — в `ruff.toml`).
- `build.sh`: `shellcheck build.sh`.

CI не пропускает замечания ruff и shellcheck.

## Проверка на телефоне

Два телефона на USB, на обоих ModKit и библиотеки MS_KIT, у гостя в настройках coop указан IP хоста. Тогда всё делает
один скрипт:

```bash
python tools/phones.py run --build                  # сборка, установка, перезапуск, связь, бой, lab.py mobs drop, журналы
python tools/phones.py run --no-deploy --lab "--kinds spells magic"
python tools/phones.py status                       # версии модов на телефонах и состояние coop
```

Шаги по отдельности: `deploy`, `restart`, `connect`, `battle [--area N] [--loop]`, `logs`. Итог — PASS/FAIL и код
выхода, журналы обоих телефонов — в `dist/phones/<время>/`. Скрипт:

- ставит архив, только если на телефоне другая версия: архив той же версии ModKit не перечитывает (для `coop` это FAIL);
- после `am force-stop` удаляет `running.lock`, иначе ModKit сочтёт перезапуск падением и выключит моды;
- включает `coop`, `coop_debug`, `coop_cheat`, `coop_lab` в `config.json`, если они выключены;
- подключает и входит в бой через консоль `coop_debug` (`Host`, `Join`, `Button_AreaStart`), без нажатий по экрану;
- после проверок ищет исключения Unity в logcat и ошибки в `modkit.log` с последнего запуска coop.

На Terra (`--area 14`) до подбора особого обелиска бой стоит и враги пропадают, поэтому сценарии `lab.py` там не идут.
Для Terra есть автобой:

```bash
python tools/terra.py --minutes 6        # перезапуск, бой на Terra вдвоём, всё до 6:00, журналы в dist/terra/<время>/
```

Скрипт нажимает кнопки окон через `coop_lab` (`Buttons`, `Click`), касаний нет. Умение и атрибут — верхняя карта.
Усиление магии — первая магия сверху слева, в каждом следующем окне следующая вправо по рядам. Сундук — первый
артефакт. Торговец — первый товар, если хватает маны (игра тогда включает Buy), затем выход. Хост встаёт на обелиски
(`Pickups`, `GoTo`), оба — на сундуки и торговца. Героев никто не водит, поэтому у обоих бессмертие полигона. Окно, которого
скрипт не знает, он пишет в вывод со списком кнопок и скриншотом.

Вручную:

Установить свежую сборку по USB:

```bash
adb push dist/coop.zip /sdcard/Download/
```

Затем в Zombix: «Моды» → «+» → `coop`. Журнал мода:

```bash
adb shell cat /sdcard/MelonLoader/com.vkslrzm.Zombix/UserData/ModKit/modkit.log | grep "\[coop\]"
```

Перед проверкой убедитесь, что в журнале есть строка `кооператив <версия> включён`.

Отладочная консоль (`coop_debug` включён на телефоне) доступна только через USB:

```bash
adb forward tcp:8771 tcp:8770
python tools/coop_dbg.py 8771 "get mgr.Time_Sec"
```

### Полигон

`coop_lab` включается в окне «Моды» (новый мод ModKit по умолчанию выключен). В бою кнопка «ПОЛИГОН» открывает
три вкладки:

- «Арена»: спавн игры, бессмертие, опыт (без опыта нет окон выбора магии, кнопка уровня героя в чите работает), стоп и
  перемотка часов, убрать или убить врагов;
- «Мобы»: любой тип врага (0–50), эпические, особые, переход;
- «Механики»: часы к боссу, босс-волна, обелиск, смена области, притягивание маны, предмет по номеру.

Те же действия с ПК через консоль: `call T:coop_lab:MagicSurvivalLab.Lab/Current.Spawn 6 10`, `.Status`, `.CoopStatus`.
Магии выдаёт `coop_cheat`, полигон зовёт его в `Spell <id> <уровень>`.

Сценарии на двух телефонах (оба в бою, на связи, с `coop`, `coop_debug`, `coop_lab` и `coop_cheat`):

```bash
python tools/lab.py mobs chests drop                 # мобы, сундуки, обрыв связи
python tools/lab.py --kinds spells magic             # 21 магия, кастуют по очереди хост и гость
python tools/lab.py magic                            # все магии, особенности, комбинации и ультимейты
python tools/lab.py --json r.json perf               # нагрузка: 200 врагов, все магии на максимум, 60 с
```

- `magic`: каждую магию, особенность, комбинацию и ультимейт сначала вызывает хост, потом гость. Хост стоит в точке
  старта, гость в 2 ед. правее; места не меняются, оба героя в кадре. Магии пункта кастуются в обход перезарядки каждые
  0,5 с (`--cast-every N` — каждые N×100 мс, 0 — как в игре). Скриншоты обоих телефонов — через 0,6 и 1,6 с после
  появления магии у кастующего. Сравнивается вид снаряда у кастующего и у друга: номер, префаб, спрайт без номера кадра.
  Поля героя, от которых зависит вид (`LookParams`, см. [MAGIC_REPLAY.ru.md](MAGIC_REPLAY.ru.md)), у кастующего и
  полученные другом должны совпасть. Разный наибольший масштаб отмечен `ИНФО`: огонь и взрывы растут по ходу анимации.
  Своя магия хоста и гостя должна выглядеть одинаково; вид, который за время пункта успел появиться только у одного
  (например, метеорит), отмечен `ИНФО`. Копии орбит у друга (Спутники, Духи, двойники; `Orbs`) сравниваются с объектами кастующего: число, картинка, размер, радиус. Ещё проверяются Щит, Электрозона, Маг. круг, Армагеддон
  и исключения в журнале игры. На каждый пункт у хоста стоят неубиваемые враги (`--targets N`, по умолчанию 3); при
  `--targets 0` магии, которым нужна цель, молчат (`ИНФО`). `--place`: после скриншотов друг отходит на 7 ед. и меряется место —
  у друга снаряд должен быть у союзника, а не у его героя (в 2 ед. снаряд почти одинаково близок к обоим). Ещё
  `--kinds` (spells, traits, combos, ults), `--items` (номера через запятую), `--caster`, `--wait` (сколько ждать
  появления), `--after` (сколько смотреть после второго скриншота). Вид, которого у друга не было в замерах, не провал (`ИНФО`), если снаряд друг повторил (быстрый
  снаряд гаснет между замерами) или это взрыв от попадания: взрыв созвездия 75–77 игра выбирает случайно у каждого.
  Если состояние друга не приходило дольше 1 с (обрыв связи), пункт
  повторяется до двух раз, затем отмечается `НЕТ`. Отчёт со скриншотами и полями вида — `magic.html`.
- `mobs`: хост вызывает мобов каждого вида, мобы стоят (`FreezeEnemies`). У гостя копии сравниваются с врагами хоста по
  номеру врага: тип, спрайт, размер на экране, обводка особых и место (до 0,3 ед.). Скриншоты хоста и гостя сняты на
  стоящих мобах. Потом мобы 3 с идут к героям: копия должна отставать не больше чем на 1,5 ед. Затем хост убивает двух,
  гость ранит двух копий: враг у хоста и копия у гостя должны пропасть с разницей не больше 1 с.
- `chests`: хост кладёт сундук, он должен появиться у гостя на том же месте. Первый сундук берёт хост, второй и
  торговца гость, после подбора сундук пропадает у обоих. Окно сундука закрывается первой картой, лавка — выходом.
  Потом артефакты, которые кладут сундуки (75 и 104, подставляются во все карты окна): их выбирает хост, затем гость.
  Сундуки и торговец от артефакта должны лечь у обоих на одних местах и лежать дальше. Между случаями сундуки убираются без подбора
  (`ClearChests`). Нужны общие сундуки (`chests` у хоста).
- `drop`: переподключение после обрыва и сошедшиеся часы.

Скриншоты обоих телефонов делаются в момент появления магии, мобов и сундука. Они и `итог.md` с таблицами (что вызвал
хост и что показалось у гостя, и наоборот; какие мобы у хоста и у гостя, когда погибли) лежат в `dist/lab/<время>/`,
папку можно задать `--dir`. Перед проверками сценарий включает обоим бессмертие, выключает опыт и снимает магии. `perf` даёт обоим все магии на максимум, 60 с держит у хоста 200 врагов и печатает таблицу цифр кадра и
сети у хоста и гостя (`--perf-sec`, `--perf-enemies`, `--perf-type`).

`lab.py` завершается с кодом 1 при любом провале, в том числе без телефонов или без adb. adb берётся из переменной
`ADB`, затем из `PATH`, затем из `%LOCALAPPDATA%\Android\Sdk\platform-tools`. `--json <файл>` записывает итог каждого
сценария: имя, прошёл, проверки, цифры. Порядок проверки на телефонах для агента — скилл `device-test`
(`.claude/skills/device-test/SKILL.md`).

В конце боя в `modkit.log` строка `сеть за … с`: байт в секунду на отправку и приём, самая длинная отправленная и
принятая строка, пинг: среднее, максимум и разброс (стандартное отклонение). `.CoopStatus` отдаёт те же цифры с начала
боя вместе со временем мода за кадр.

Отдельный сервер и проверка связи без игры:

```bash
python server/coop_server.py --port 8766
python server/coop_client.py <IP> 8766    # затем команда join
```

## Протокол v2

JSON-строки (UTF-8, одна строка — одно сообщение, не длиннее 16 КБ) поверх TCP, порт по умолчанию 8766.

- **Клиент → сервер:** `CREATE_ROOM`, `JOIN_ROOM`, `PLAYER_STATE`, `EVENT`, `PING`, `LEAVE_ROOM`.
- **Сервер → клиент:** `WELCOME`, `ROOM_CREATED`, `ROOM_JOINED`, `PLAYER_JOINED`, `PLAYER_LEFT`, `REMOTE_PLAYER_STATE`,
  `REMOTE_EVENT`, `PONG`, `ERROR`.

Хост в игре подключён к своему серверу без сокета (`CoopServer.ConnectLocal`, `CoopClient.StartLocal`) с той же логикой
комнат, слотов и выхода и отправляет `CREATE_ROOM`. Гость после обрыва возвращается в комнату `JOIN_ROOM` с её кодом.
`PLAYER_STATE` и `EVENT` сервер проверяет `Utf8JsonReader` без дерева JSON и пересылает исходные байты `state`/`event`:
ответы на проводе те же, что раньше. `JOIN_ROOM` с пустым
кодом заходит в комнату на сервере; если комнат нет, отдельный сервер создаёт её, а сервер в игре хоста отвечает
`room_not_found` («Хост ещё не создал игру»), и клиент повторяет попытку. Если порт закрыт, клиент перебирает порты
от заданного до +4.

Поле `protocol` в `CREATE_ROOM`/`JOIN_ROOM`: нет поля — старый клиент, пускаем; иначе только целое `2`, всё остальное —
`protocol_mismatch`. Версию самого мода сервер не сверяет.

Коды ошибок: `room_full`, `room_not_found`, `protocol_mismatch`, `server_busy` (подключений или комнат слишком много),
`rate_limited` (слишком частые входы), `not_in_room`, `invalid_json`, `invalid_message`, `message_too_large`,
`unknown_type`.

Ограничения встроенного сервера: 32 подключения, 8 с одного адреса, 16 комнат, 60 входов в комнату в минуту с адреса,
30 с на вход в комнату после подключения, 40 с без данных — отключение.

Медленный клиент: когда для него в очереди 96 строк, встроенный сервер пропускает новые состояния игроков, а события
отправляет дальше; отключает клиента, только если очередь на 512 строк всё же переполнилась. `coop_server.py` состояния
не пропускает и отключает клиента при 512 КБ в очереди.

## Выпуск новой версии

Изменения между релизами пишутся в раздел `## Не выпущено` в начале `.github/release_notes.md`: сначала по-английски,
затем то же по-русски после строки `**По-русски:**`.

1. Переименуйте `## Не выпущено` в `## Co-op <версия>`. В описание релиза попадают только разделы, которых не было в
   прошлом опубликованном релизе (`tools/release_notes.py`). Остальная история остаётся в файле.
2. Соберите кандидата командой `VERSION=<версия> bash build.sh`, проверьте его на двух или более телефонах по
   [чек-листу](RELEASE_CHECKLIST.ru.md) и запишите результаты в `docs/device-tests/<версия>.md` (английский) и
   `docs/device-tests/<версия>.ru.md` (русский).
3. Закоммитьте это в `main`, поставьте на коммит метку и отправьте её:

   ```bash
   git tag v1.7.9 && git push origin v1.7.9
   ```

   GitHub соберёт мод с версией из метки, прогонит тесты и опубликует релиз `v<версия>` с `coop.zip`; результаты
   проверки попадут в описание релиза. Без файла результатов релиз не публикуется; русский файл добавляется, если он
   есть.

Инструменты разработчика (`coop_debug`, `coop_cheat`, `coop_lab`) выходят отдельно по метке `tools-<версия>`: см.
